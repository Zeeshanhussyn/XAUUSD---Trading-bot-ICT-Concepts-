## 5. Sample size — a problem, stated plainly

The baseline produces **88 tradeable setups in 5.8 years**
— about **15 per year**.

`PREREGISTRATION.md` §5 asks for 400+ trades for initial feasibility and 800+
preferred. Extrapolating this rate across development plus validation (~7.8
years) gives roughly **118** — far below that floor.

This is a structural property of the pre-registered baseline, found before any
backtest has been run, which is the right time to find it. It is reported here
rather than fixed, because the founding brief is explicit: *"Never force extra
trades merely to increase sample."* Loosening a rule now, having seen that the
strict version yields few setups, is a decision for the user to take knowingly
and for this document to record — not one to slip in quietly.

For reference, the STRICT HTF gate (a planned WP10 comparison, not the
baseline) would leave 64 setups before reachability — 
fewer still, not more.

## 7. Verdict

Every detector works, is strictly causal, and is covered by known-answer
tests. The feature layer is ready for Work Package 7 (execution and cost
model).

**Carried forward as an open risk:** at the baseline's setup frequency, Phase 1
will not reach the pre-registered sample-size floor. That does not by itself
invalidate the research — the brief allows years and regime coverage to
substitute for raw count — but any conclusion drawn later must state the
sample it rests on, and a null result on ~200 trades is weaker evidence than
a null result on 800.
